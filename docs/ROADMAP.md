# 마일스톤

각 단계는 필요한 검증을 마친 뒤 완료로 표시합니다. 2026-10-16 현재 main(`7231abc`)까지가 M1 진행 중 상태입니다.

## M1 수집·신뢰도 확보 (진행 중)

**완료된 것**: `wire.jsonl` 허용 이벤트 추출, 오프셋·tail-hash·skipping 증분, `inspect`·`summary`·`validate`·`quota` 명령, 외부 리뷰 2라운드 반영(테스트 61 → 77), 실데이터 첫 검증(23파일 0 손상, subagent 대조 match).

**관찰 포인트** — 평소 사용으로 자동 축적, 결론이 나오면 여기에 기록:

- 쿼터 계량 실측: 2026-10-15의 6시간 73샘플은 전량 0이었으나 10-16에 실시간 계량 확인(5시간 창 0.1409, 월 0.0038). 구독 주기 기준 반영 지연으로 해석. `quota` 주기 실행으로 0→비-0 전이와 추세를 계속 감시합니다.
- `inputCacheCreation`이 누적 5,100만+ cache-read에서도 0 — 계속 관찰.
- 세션 재개(resume) 시 이어 쓰기 여부, 이벤트 append 형태 유지, `token_counting.measured`와 `usage.record`의 1:1 유지, `usage.record` ↔ `agent.message.appended` 차이 원인.

**완료 조건**: 관찰 포인트마다 결론(정상·이슈)이 문서로 남고, 재현된 이슈는 수정되거나 known-issues에 좌표와 함께 기록.

## M2 SQLite 저장

**목적**: 장기 추이와 쿼터 추적의 기반. JSON 오프셋 파일에서 SQLite로 옮깁니다.

- 스키마 버전과 마이그레이션.
- `usage.record` UPSERT — 파일 신원+오프셋 중복 제거 유지, 누락 필드 허용.
- 오프셋·tail_hash·skipping 상태를 같은 DB에 통합.
- usage-monitor의 WAL·UPSERT 패턴 계승, 스캔-저장을 한 트랜잭션으로.

**완료 조건**: 기존 증분 동작이 SQLite 기반으로 동등하게 동작하고 테스트로 보존.

## M3 쿼터 추적기

**목적**: 실사용 중 "5시간 창이 얼마나 남았나"를 알기 — 10-16에 live 계량이 확인됐으므로 가치가 확정됐습니다.

- `quota` 주기 폴링 누적(SQLite), 5시간 버킷 추세와 소진 예측, 월간 누적.
- 서버 미실행·401·리디렉션 경로는 기존 방어 재사용.
- 반영 지연(구독 주기 기준)을 추정치에 반영할지 여부는 M1 관찰 데이터로 결정.

**완료 조건**: 켜두면 창별 사용률의 시간축이 쌓이고 임계(예: 80%) 경고가 나온다.

## M4 로컬 서버·대시보드

- HTTP 화면: 일별 토큰 차트, 모델별(k3 등)·에이전트별 분포, 캐시 비중, 쿼터 창, 검증 리포트.
- v0는 폴링으로 — SSE는 usage-monitor의 것을 참고하되 이 단계에선 과합니다.

**완료 조건**: 브라우저에서 오늘 `summary`·`quota`로 수동 확인한 내용이 화면에 보인다.

## M5 Windows 운영

- 트레이 위젯, 로그인 시 자동 실행, 설치·제거.
- usage-monitor의 교훈을 처음부터 반영: 코드 서명(SignPath) 계획을 배포 설계에 포함 — "서명 없는 인스톨러가 Smart App Control에서 막힌" 사례(2026-10-15)의 재발 방지.

**완료 조건**: 재부팅 후 트레이에서 사용량·쿼터 확인, 설치·제거가 남는 것 없이 동작.
