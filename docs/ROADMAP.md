# 마일스톤

각 단계는 필요한 검증을 마친 뒤 완료로 표시합니다.

## M1 수집·신뢰도 확보 — 완료 (2026-10-16)

**구현 완료**: `wire.jsonl` 허용 이벤트 추출, 오프셋·tail-hash·skipping 증분, `inspect`·`summary`·`validate`·`quota` 명령, 외부 리뷰 2라운드 반영(테스트 61 → 77).

**관찰 결론** (2026-10-15~16 실측):

- **쿼터 계량**: 10-15에 6시간 73샘플로 전 창 0을 관측했으나 10-16에 실시간 계량 확인. 같은 날 90분 새 5시간 창이 0.1409 → 0.6694, 월간 0.0038 → 0.0182로 상승. 구독 주기 기준으로 소비 반영에 시간이 걸리고, 반영 후에는 실시간으로 따라갑니다. 계정의 첫 관측일 0은 반영 지연으로 결론.
- **`inputCacheCreation`**: 누적 cache-read 5,100만+에서도 0. 제품이 이 항목을 기록하지 않음(또는 항상 0)으로 결론. 값이 생기면 집계에 그대로 반영되며 다시 관찰.
- **세션 구조·재개**: 세션 16개(메인 1 + 사용자의 별도 세션 15), 에이전트 폴드별 wire.jsonl, append 이어 쓰기 유지. 증분 실행 1회차 550건·2회차 0건·reset 0으로 이어 받기 확인. 동시 활성 세션 여러 개에서의 멀티 세션 집계 정상.
- **append 형태**: 26파일 전수에서 malformed·unreadable·oversized 0. 기존 줄 변경·잘림 없음.
- **`usage.record` ↔ `token_counting.measured`**: 요청당 1건씩 짝. 같은 요청의 `time`이 1~2ms 어긋나 타임스탬프 집합 비교에는 의사 불일치가 나타나므로 건수·합계로 대조. main의 measured 1건 누락은 진행 중 요청의 시점 차이로 확인(마지막 usage.record가 조회 직전).
- **`usage.record` ↔ `agent.message.appended`·`turn_recorded` 차이**: 메시지·턴·컨텍스트 단위라 합계가 다름 — 단위 차이가 정상. `validate`의 "확인 필요" 표기 유지.

**실데이터 첫 리포트** (10-16): `usage.record` 551건, input 262만·output 71만·cache-read 5,140만, 모델 2종(`kimi-for-coding`·`k3`), main 223·subagents 328건, subagent 대조 match(중복 집계 없음 실증).

## M2 SQLite 저장

**목적**: 장기 추이와 쿼터 추적의 기반. JSON 오프셋 파일에서 SQLite로 옮깁니다.

- 스키마 버전과 마이그레이션.
- `usage.record` UPSERT — 파일 신원+오프셋 중복 제거 유지, 누락 필드 허용.
- 오프셋·tail_hash·skipping 상태를 같은 DB에 통합.
- usage-monitor의 WAL·UPSERT 패턴 계승, 스캔-저장을 한 트랜잭션으로.

**완료 조건**: 기존 증분 동작이 SQLite 기반으로 동등하게 동작하고 테스트로 보존.

## M3 쿼터 추적기

**목적**: 실사용 중 "5시간 창이 얼마나 남았나"를 알기 — M1에서 live 계량이 확인됐으므로 가치가 확정됐습니다.

- `quota` 주기 폴링 누적(SQLite), 5시간 버킷 추세와 소진 예측, 월간 누적.
- 서버 미실행·401·리디렉션 경로는 기존 방어 재사용.
- 반영 지연(구독 주기 기준, M1 관측)을 추정치에 반영할지 여부는 M3 설계 시 결정.

**완료 조건**: 켜두면 창별 사용률의 시간축이 쌓이고 임계(예: 80%) 경고가 나온다.

## M4 로컬 서버·대시보드

- HTTP 화면: 일별 토큰 차트, 모델별(k3 등)·에이전트별 분포, 캐시 비중, 쿼터 창, 검증 리포트.
- v0는 폴링으로 — SSE는 usage-monitor의 것을 참고하되 이 단계에선 과합니다.

**완료 조건**: 브라우저에서 `summary`·`quota`로 확인한 내용이 화면에 보인다.

## M5 Windows 운영

- 트레이 위젯, 로그인 시 자동 실행, 설치·제거.
- usage-monitor의 교훈을 처음부터 반영: 코드 서명(SignPath) 계획을 배포 설계에 포함 — "서명 없는 인스톨러가 Smart App Control에서 막힌" 사례(2026-10-15)의 재발 방지.

**완료 조건**: 재부팅 후 트레이에서 사용량·쿼터 확인, 설치·제거가 남는 것 없이 동작.
